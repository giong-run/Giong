# GIONG-E0006: read used after recv

Raised by `TcpStream`, `UnixStream` and `UdpSocket`. In code: `giong::error::Code::MixedReads`.

## What happened

A one-off read (`read`, `read_from`), or `splice_to`, was used on a stream or socket that already has a multishot receive (`recv`, `recv_from`) running. The kernel keeps delivering data into the multishot receive, so a one-off read would see the data out of order, and `splice_to` would skip what `recv` had taken in already.

## How to fix it

- Use one way of reading per stream or socket: `recv`/`recv_from` (buffers from the runtime's pool, best for many connections), `read`/`read_from` (your own buffer) or `splice_to` (bytes moved to another stream inside the kernel).
- To forward a stream that `recv` has already read from, write what `recv` returns with `write_all`.

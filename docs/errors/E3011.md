# GIONG-E3011: statement refused before sending

Raised by giong-postgres, `Pool::query`, `Pool::query_one`, `Pool::query_opt` and `Pool::execute`. In code: `giong::error::Code::PostgresStatement`.

## What happened

The statement was refused before anything was sent. It controls a transaction (`BEGIN`, `START TRANSACTION`, `COMMIT`, `END`, `ROLLBACK`, `ABORT`, `SAVEPOINT`, `RELEASE`, `PREPARE TRANSACTION`), and the pool's own methods run statements on connections that several tasks share at once: a transaction begun there would take in the statements of the other tasks, and a `COMMIT` there commits nothing of yours.

## How to fix it

- Take a connection for the task with `Pool::get`, and run the transaction on it with `transaction()`: dropping the transaction without `commit` rolls it back.
- A whole transaction in one string (`BEGIN; ...; COMMIT`) can go through `Pool::batch_execute`; if it leaves a transaction open, the connection is closed and everything since `BEGIN` is rolled back (GIONG-E3008).

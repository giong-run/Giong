# GIONG-E2012: TLS keys used up

Raised by giong-tls, `TlsStream::write_all` on a connection encrypted by the kernel. In code: `giong::error::Code::TlsKeysExhausted`.

## What happened

An AES-GCM key may only encrypt so many TLS records before its security weakens (2^24 records in rustls, about 16.7 million). On TLS 1.3 giong-tls then changes keys with a `KeyUpdate`, as rustls does. This connection could not: it uses TLS 1.2, which has no way to change keys, or a kernel older than Linux 6.14 encrypts it. As rustls does in that case, the connection sent `close_notify` and refuses to send more.

A connection that sends many small records over a long time, such as a busy keep-alive or database connection, can reach the limit in hours.

## How to fix it

- Open a new connection; HTTP clients and connection pools do this when a connection ends.
- Prefer TLS 1.3, and Linux 6.14 or newer when the kernel encrypts the connection.

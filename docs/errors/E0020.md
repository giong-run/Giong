# GIONG-E0020: the deadline passed

Raised by `giong::task::with_deadline`, `giong::task::with_timeout` and a `giong::task::Scope` made with `Scope::with_deadline` or `Scope::with_timeout`, when their `Cancelled` error becomes an `io::Error` (by `?` in a function returning `io::Result`). The error kind is `TimedOut`. In code: `giong::error::Code::DeadlineExceeded`. A task in a `TaskGroup` whose inherited deadline passes ends with `JoinError::DeadlineExceeded` instead.

## What happened

The work ran under a deadline and did not finish before it. giong dropped the work, which cancels its I/O: on io_uring the kernel had already cancelled every operation that was waiting on a peer at the deadline (they carry it as a linked timeout), and on epoll the deadline's timer ended them. Code inside the work never runs after its deadline. Nested deadlines take the earlier one, so the deadline that passed may be an outer one: `giong::task::deadline()` tells which deadline is in force at any point.

## How to fix it

- Give the work more time if the deadline is too tight for it.
- Otherwise find the slow step: log `giong::task::remaining()` between the steps of the work, or look at the worker in `giong-mcp`. A peer that does not answer, a slow DNS lookup, or another task keeping the worker busy (one worker runs every task on its core) are the usual causes.
- Background work that must outlive the request should be started with `giong::spawn`, which does not inherit the deadline, rather than in the request's scope or task group.

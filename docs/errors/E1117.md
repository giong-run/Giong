# GIONG-E1117: too many HTTP/2 control frames

Sent by giong-http's server to an HTTP/2 client, in the debug data of the GOAWAY frame (`ENHANCE_YOUR_CALM`) that closes the connection. In code: `giong::error::Code::Http2Flood`.

## What happened

The client sent more frames that do no work than the server allows in a short time: PING, SETTINGS and their acknowledgements, PRIORITY, empty DATA or CONTINUATION frames, WINDOW_UPDATE frames when nothing waits to be sent, frames for streams already closed, header blocks for streams the server ignores, and frame types the server does not know. Each costs the server some work and buys the client nothing, so a stream of them is a flood (the "ping flood", "settings flood", "empty frames" and CONTINUATION attacks). The server allows a burst of 1,000 such frames and then 500 per second.

## How to fix it

- If the client is yours: send keep-alive PINGs every few seconds at most, and SETTINGS only when something changes. Send WINDOW_UPDATE as data is consumed, not on a timer.
- Otherwise the client is misbehaving or attacking, and closing the connection is the intended outcome.

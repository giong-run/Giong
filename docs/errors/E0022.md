# GIONG-E0022: task-local value not set

Raised by `LocalKey::with` and `LocalKey::get` (keys declared with `giong::task_local!`), as a panic. In code: `giong::error::Code::TaskLocalNotSet`.

## What happened

A task-local value was read where no `KEY.scope(value, future)` around the code sets it. Task-local values are seen by everything the future given to `scope` polls, by the children of a `giong::task::Scope` inside it, and by tasks started there with `TaskGroup::spawn`. They are not passed to tasks started with plain `giong::spawn`, nor to `Handle::spawn_on`, which runs on another worker. This is a bug in the calling code, so giong panics instead of returning an error.

## How to fix it

- Wrap the work in `KEY.scope(value, async { ... })`, or set it once per request where the request is accepted.
- Start the tasks that should see the value with a `Scope` or a `TaskGroup` instead of `giong::spawn`, or pass the value to the task yourself.
- Where the value may be missing, read it with `try_with` or `try_get`, which return `None` instead of panicking.

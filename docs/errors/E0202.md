# GIONG-E0202: file offset out of range

Raised by `giong::fs::File::read_at`, `write_at` and `write_all_at`. In code: `giong::error::Code::OffsetOutOfRange`.

## What happened

The offset is above `i64::MAX` (9,223,372,036,854,775,807), the largest file offset Linux has. Nothing was read or written. Such an offset is almost always the result of arithmetic that wrapped around, or of `u64::MAX` used as a marker. giong checks it before asking the kernel because io_uring reads an offset of `u64::MAX` as "the file's current position": without the check, the read or write would land wherever the descriptor's position happens to be, and only on the io_uring driver (the epoll driver's `pread`/`pwrite` would fail with `EINVAL`). For `write_all_at`, the offset of a later chunk (`offset` plus the bytes already written) can be the one out of range.

## How to fix it

- Check the arithmetic that computed the offset: use `checked_add` and handle the overflow.
- A `giong::fs::File` has no cursor; every read and write names its offset. To append, open the file with `OpenOptions::new().append(true)`, and every write goes to the end whatever offset it names.
